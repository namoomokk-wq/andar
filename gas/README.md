# 구글 시트 + Apps Script 연결 방법 (약 5분)

1. https://sheets.google.com 에서 새 스프레드시트를 만든다. (이름 예: `ANDAR IN. MOTION 신청`)
2. 그 시트의 메뉴 **확장 프로그램 → Apps Script** 를 연다. (script.google.com에서 따로 만든 스크립트는 시트에 기록하지 못한다)
3. 기본 `Code.gs` 내용을 지우고 이 폴더의 `Code.gs` 전체를 붙여넣고 저장한다.
4. 우측 상단 **배포 → 새 배포 → 유형: 웹 앱**
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자**
   - 배포 → 권한 승인 → 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/.../exec`)을 복사한다.
5. `config.js`의 `GAS_URL`에 그 URL을 붙여넣는다. (비워 두면 사이트가 브라우저 localStorage에 저장하는 mock 모드로 동작)
6. 배포 URL을 브라우저로 열어 `{"ok":true,"message":"ANDAR IN. MOTION apply endpoint"}`가 보이는지 확인한다.
7. 신청 테스트 후 시트의 `신청` 탭(첫 신청 때 자동 생성)에 행이 쌓이는지 확인한다.

## 설정 동기화 (config.js → Code.gs)
- 최대 세션 수(`MAX_SESSIONS`)·마감 시각(`DEADLINE`)·시간표(`DATES`, `SCHEDULE`)·사이즈(`SIZES`)는 `config.js`가 원본이다.
- 바꾼 뒤 `node gas/sync.js`를 실행하면 `Code.gs`의 생성 블록(`// ---- config.js에서 생성됨` ~ `// ---- 생성 끝 ----`)이 갱신된다. 이 블록은 직접 고치지 않는다.
- 어긋나 있으면 사이트가 보낸 세션·사이즈가 서버에서 거부되거나, 마감 시각이 화면과 서버에서 달라진다. 배포 전에 `node gas/sync.js --check`로 확인할 수 있다. (어긋나면 종료 코드 1)
- `Code.gs`를 수정하면 **배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전**으로 다시 배포해야 반영된다. (URL은 동일. **새 배포**를 누르면 URL이 바뀐다)

## 접수 동작 (`Code.gs`)
- **요청 종류**
  - `action: "check"`: 1단계 NEXT에서 하는 중복 사전 확인. 읽기 전용이라 잠금 없이 바로 응답한다.
  - 그 외: 최종 신청. 검증 → 잠금 → 중복 확인 → 기록 순서로 처리한다.
- **검증**: 필수값(성함·성별·연락처·안다르 아이디·상의·하의), 연락처 형식, 입력 길이, 세션(시간표에 있는 값, 1~`MAX_SESSIONS`개, 중복 없음), 성별별 사이즈 목록(여성은 브라탑, STRETCH YOUR RUN 선택 시 운동화 포함).
- **마감**: `DEADLINE` 이후에는 사전 확인과 신청 모두 `클래스 신청이 마감되었습니다.`로 거절한다. 서버 실제 시각 기준이다.
- **중복 차단**: 연락처, 안다르 아이디, 인스타 아이디(입력 시). 아이디는 공백·대소문자·인스타의 `@`를 무시하고 비교한다.
- **봇 의심**: 허니팟 칸(`website`)이 채워졌거나 신청 화면을 연 지 3초(`MIN_ELAPSED_SEC`) 안에 제출하면, 저장하지 않고 성공처럼 응답한다. (테스트 중 "완료인데 시트에 없음"의 흔한 원인)
- **동시 접수**: 검증은 잠금 밖에서 끝내고, 잠금(최대 20초 대기)은 중복 확인·기록 구간에만 잡는다. 중복 확인은 연락처·안다르 아이디·인스타 아이디 열만 읽는다. 기록 후 `SpreadsheetApp.flush()`로 확정한 뒤 잠금을 풀어, 바로 다음 요청의 중복 확인에 반영되게 한다.
- **오류 응답**: 잠금 대기 초과 등은 `서버 오류: ...`로 응답하고, 사이트가 이를 받아 최대 6회까지 자동 재시도한다. 요청 본문이 깨진 경우는 `요청 형식이 올바르지 않아요.`로 응답하며 재시도하지 않는다.

## 시트 구조
- 탭 이름: `신청` (없으면 첫 신청 때 만들고 1행에 헤더를 쓴다)
- 열 순서: `접수시각, 성함, 연락처, 안다르 아이디, 세션1, 세션2, 성별, 브라탑, 상의, 하의, 신발, 인스타 아이디, 마케팅 동의`
  - 남성의 브라탑, 러닝을 고르지 않은 경우의 신발은 `-`
  - 마케팅 동의는 `Y` / `N`
  - 연락처는 앞자리 0이 사라지지 않도록 텍스트로 저장하고, `= + - @`로 시작하는 입력값은 수식으로 실행되지 않도록 앞에 `'`를 붙인다.
- 중복 확인이 열 위치(연락처 C열, 안다르 아이디 D열, 인스타 아이디 L열)에 의존하므로 운영 중에는 탭 이름과 열 순서를 바꾸지 않는다.

## 마감 화면 테스트 (사이트)
- 사이트 주소 끝에 `?closed`를 붙이면 마감 시각으로, `?now=2026-10-14T23:59:30+09:00`처럼 붙이면 그 시각부터 시간이 흐르는 것처럼 화면이 동작한다. 왼쪽 아래에 분홍색 TEST 표시가 뜬다.
- 화면 표시만 바뀌며, 실제 접수 마감은 위 서버 로직이 실제 시각으로 판단한다.

## 주의
- 시트에는 연락처 등 개인정보가 쌓이므로 공유 범위를 최소한으로 유지하고, 행사 후 파기한다.
- Apps Script 웹 앱은 동시 실행 수 제한(계정당 약 30건)이 있다. 오픈 직후 몰리면 일부 요청이 실패할 수 있으나 사이트가 자동 재시도한다.
